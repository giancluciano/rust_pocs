$ what is swarms-rs?

A Rust framework for LLM agents
that work as a team

01 · agent

Agent

An LLM plus a system prompt, tools, and a loop with retries. Built with a fluent builder.

02 · tool

Tools

Rust functions the model can call. Arguments are typed structs with a JSON schema. MCP servers work too.

03 · swarm

Workflows

Ready-made team shapes: Sequential, Concurrent, AgentRearrange, DAG, SwarmRouter.

  • One sentence: swarms-rs lets you define LLM agents in Rust and combine them into teams.
  • Three ideas: an agent is a model plus prompt plus tools; tools are typed Rust functions; workflows are prebuilt team shapes (in a row, in parallel, a graph, or a router that picks one).
  • It's the Rust sibling of the Python Swarms project. Still 0.3, so it's young.
  • Any OpenAI-compatible API works through a base URL. I used DeepSeek.

Two agents, running in parallel

main.rs
let client = OpenAI::from_url(base_url, api_key)
    .set_model("deepseek-chat");

let researcher = client.agent_builder()
    .agent_name("Researcher")
    .system_prompt("Find facts. Never invent data.")
    .add_tool(SearchTool)
    .max_loops(3)
    .build();

let team = ConcurrentWorkflow::builder()
    .agents(vec![Box::new(researcher), Box::new(critic)])
    .build();

let report = team.run("Compare Rust agent frameworks").await?;
Builder APIPrompt, tools, loops and temperature in one chain.
Typed toolsSearchTool is a Rust struct; its schema goes to the model.
Async all the wayWorkflows are Tokio futures; just .await.
  • Point at the builder: this is the whole agent definition.
  • add_tool takes a typed tool. The schema comes from the struct, so a wrong argument type fails at compile time, not in production.
  • ConcurrentWorkflow runs both agents on the same task in parallel.

Pros & cons, from building the POC

// what worked

  • Fast and type-safeTool arguments are Rust structs, so mistakes show up at compile time. Ships as a single binary.
  • Multi-agent patterns built inSequential, concurrent, rearrange, DAG and router. No need to write orchestration from scratch.
  • Tokio-native concurrencyAgents are async, so two searchers in parallel is just a tokio::join!.

// what hurt

  • Sparse docs and examplesdocs.rs plus a handful of examples. I read the crate source to learn the builder options and how tools behave.
  • Tool-calling quirksAgents return free text and don't stop after replying. Tools write into shared state; a stop marker ends each agent.
  • Heavy build6k lines of code pulled in 354 crates and 2.6 GB of build output.
  • Pros: for a Rust team it feels at home: typed tools, async, one binary. The workflow types save boilerplate.
  • Cons: expect to open the source; the docs won't answer everything.
  • Tool quirks, from the POC: workflows hand back text, so every agent reports through a tool that writes into shared state; the code never parses the model's reply. In 0.3 a text reply doesn't stop the agent either, so the last tool returns a <<DONE>> marker registered as a stop word.
  • Build: most of it is normal for Rust with tokio, reqwest and an HTML parser (193 crates without swarms-rs). swarms-rs adds about 78, including a second TLS library (OpenSSL) and older versions of crates I already use. One Cargo.toml line, debug = "line-tables-only", took the build folder from 5.5 GB to 2.6 GB. The binary itself is 12 MB.

Source: GitHub · 28 Oct 2026

  • Stars tell the story: swarms-rs is tiny, ~230× fewer stars than LangGraph.
  • Rig is the other Rust option, ~50× more stars. Broader building blocks (RAG, vector stores, many native providers) but no prebuilt multi-agent shapes; you wire them yourself.
  • LangGraph is the mainstream Python choice: past 1.0, huge ecosystem. Trade-off: Python runtime and deployment.
  • If asked about providers: swarms-rs ships OpenAI-compatible and Anthropic; the others support far more.
  • The POC uses swarms-rs 0.3.0.

Demo

  • The POC ran before the talk: a New Year's Eve planner. Input: "the coastline of Santa Catarina", 12 people, Dec 30 – Jan 2.
  • Open src/main.rs and walk the five steps: one planner agent proposes 15 cities → ConcurrentWorkflow runs 15 fireworks researchers in parallel, with web search → plain code searches Airbnb → SequentialWorkflow: curator, then travel writer → Markdown report.
  • Open the report in output/: 3 of 15 cities have a confirmed show, each with its source; 20 stays picked for the group, with reasons.
  • Numbers: about 2.5 minutes, 41 web searches, 77 Airbnb requests.
  • If there's time, one lesson: the first run "confirmed" two cities from last year's announcements. "Réveillon 2026" means Dec 31, 2025. Fixed in the prompt, plus a check in the submit tool.
